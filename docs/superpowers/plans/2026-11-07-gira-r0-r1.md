# GIRA R0+R1 "Primer pitido" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cada evento nuevo, fecha extra o cambio de venta de un artista seguido en Europa+UK publicado en Ticketmaster llega al servidor de Discord GIRA en ≤ 10 min (⭐⭐⭐) / ≤ 25 min (resto), sin duplicados y respetando las horas de silencio.

**Architecture:** Monorepo TypeScript con npm workspaces. `packages/core` contiene el dominio puro (horas, silencio, tipos de preventa, normalización de Ticketmaster, detección de cambios, mensajes de Discord). `apps/worker` es un Cloudflare Worker con un cron `*/5` que barre Ticketmaster por lotes de `attractionId`, guarda en D1 y publica en Discord por REST. `apps/jobs` contiene trabajos de GitHub Actions (resolver artistas, montar el servidor de Discord).

**Tech Stack:** Node 22, TypeScript 5, npm workspaces, Vitest, `@cloudflare/vitest-pool-workers`, Wrangler, Cloudflare Workers + D1, Discord REST API v10, Ticketmaster Discovery v2.

**Spec:** `docs/plan/` — sobre todo `03-story-map.md` (R1), `04-historias.md` (H-01, H-10, H-20, H-30, H-40, H-50, H-80–H-83), `05-arquitectura.md`, `06-modelo-datos.md`, `07-dashboards.md` (estructura Discord) y `01-auditoria.md` §6 (hallazgos de Ticketmaster).

## Global Constraints

- Idioma de la interfaz y de los mensajes: **español**. Commits y código en inglés.
- Horas guardadas en **UTC ISO-8601**; mostradas en **Europe/Madrid** y **Europe/London** (y local del recinto si difiere).
- Horas de silencio: **01:00–08:00 Europe/Madrid**. Urgente = venta/preventa en < 60 min, sala de espera abierta, o fecha extra de un artista seguido.
- Solo información: nunca URLs con `queueittoken`, nunca automatizar nada en una ticketera.
- Ningún secreto en el repo (es público). Secretos del Worker: `TICKETMASTER_API_KEY`, `DISCORD_BOT_TOKEN`. Logs: solo recuentos y códigos.
- Ticketmaster: ≤ 5.000 llamadas/día; freno al **80 %** (4.000). `attractionId` admite varios IDs separados por comas (medido). `size × page < 1000`.
- Workers gratis: **10 ms CPU** por invocación, 50 subpeticiones, KV no se usa en R1.
- Países de Fase 1 (Europa + UK): `GB, IE, ES, PT, FR, DE, IT, NL, BE, LU, AT, CH, DK, SE, NO, FI, PL, CZ, HU, GR, HR, RO, SK, SI, BG, EE, LV, LT, IS, MT, CY, RS, TR`.
- Servidor Discord: ID `1568641743853715516`. El montaje es idempotente y **nunca borra** canales.

## Review Focus

1. **Primer barrido (arranque):** al no haber nada guardado de un artista, guardar en silencio; un primer ciclo no debe generar cientos de avisos. → test en Task 6 y Task 9.
2. **Cambio de horario y husos:** una venta a las 00:30Z del 28-mar-2027 es 01:30 en Madrid; recintos en Londres muestran su hora local. → tests en Task 2.
3. **Duplicados comerciales de Ticketmaster** ("… | VIP Packages" de la misma fecha) no son fechas extra. → tests en Task 4 y Task 6.
4. **Cuota agotada o 429 a mitad de ciclo:** se corta limpio, no se corrompe estado y el siguiente ciclo sigue. → test en Task 9.
5. **Fallo o 429 de Discord:** el aviso queda pendiente y se reintenta sin duplicarse. → test en Task 9.
